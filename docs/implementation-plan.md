# ResearchFlow 实施计划

## 已确认的边界

使用 LangGraph + Python 终端，不做 Web 界面。一个调度 Agent、检索/总结/写作三个执行 Agent；固定流程，两次审批。代码以最小可运行闭环为准，不建立通用 Agent 平台。

- arXiv MCP 为主，Google Scholar MCP 补充；免费实现，Scholar 不可用时记录并继续。
- 新任务新建 `sessions/日期时间_主题_短ID/`；审批修改、失败重试和恢复使用原目录。
- 默认最多 30 篇候选、10 篇入选，具体要求在计划审批时确认。
- 入选论文下载公开 PDF、提取正文；失败退回摘要并标注，搜索片段不能冒充摘要或正文。
- PDF、提取文本、逐篇笔记、计划、总结、提纲、最终报告分目录保存，可读文件名、保留版本。
- 默认中文 Markdown 报告约 3000–5000 字，附引用、JSON 材料包和 BibTeX；具体语言与篇幅可由本次需求指定。
- 两次审批均支持通过、反馈修改、退出；恢复不能默认批准。
- 模型地址、名称和密钥通过 `.env` 配置；四个角色默认共用模型。

## 实现顺序

1. 会话存储、LangGraph 固定图、版本化产物与审批暂停/恢复。
2. MCP 接入、检索筛选、PDF 下载与提取、证据卡及引用校验。
3. 终端交互、文件导出、模型配置、失败续跑。
4. 离线测试、真实 MCP 联调、运行说明、示例及调研记录。

## 技术决定

- 使用已有 Python 3.12 隔离环境，uv 固定依赖；项目兼容 Python 3.11–3.12。
- LangGraph `StateGraph`、`interrupt`、`Command(resume=...)`；异步 MCP 与 SQLite checkpointer。
- arXiv：`arxiv-mcp-server==0.7.2`；Scholar：基于已核对上游的最小本地适配，来源与修改见 `third_party/google_scholar/README.md`。
- HTTPX 下载原始 PDF，PyMuPDF 提取文字，不实现 OCR 或图表理解。
- 文件锁防止同一会话并发运行；产物哈希检查防止旧审批授权被改动的文件。
- 首版不导入人工直接编辑的阶段文件，使用审批反馈修订；不接入付费检索服务。

## 验收

未审批不检索/不写作；旧审批与被修改的文件不能继续；修改后重新审批；重启后恢复原审批点；重复审批不重复写作；检索失败可重试；PDF 真实保存与可追溯；引用只能来自批准材料。

离线演示必须明确标注模拟数据。真实模型端到端运行需要本地配置模型密钥，不把模拟产出当作真实研究结果。
