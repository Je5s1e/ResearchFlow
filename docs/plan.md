# ResearchFlow 框架设计

## 目标

在 Python 终端完成固定流程的论文调研，展示真实 Agent 任务交接、审批前暂停和审批后继续。默认 30 篇候选、10 篇入选，输出中文 Markdown 报告。

## 结构与分工

- 调度 Agent：解析需求、生成计划、派发任务、检查材料、请求审批。
- 检索 Agent：通过 arXiv/Scholar MCP 检索，筛选去重，下载入选 PDF，提取正文与证据。
- 总结 Agent：生成逐项带引用的研究总结、方法对比和提纲。
- 写作 Agent：依据批准材料生成最终报告。
- LangGraph：固定节点、允许的修改回路、两次审批、SQLite 持久化。
- CLI：输入需求、展示阶段与真实消息、审批、退出与续跑。

## 流程

```text
计划 → 计划审批 → 检索/PDF/证据 → 总结与提纲 → 材料审批 → 写作 → 导出
```

计划修改回到计划阶段；材料修改可选择补充检索、修改总结或调整计划。计划变化使下游审批失效。模型不能更改图的边或批准产物。

## 状态与文件

每个新任务建立 `sessions/日期时间_主题_短ID/`，恢复沿用原目录。会话中保存 SQLite 状态、PDF、逐页提取文本、逐篇笔记、版本化阶段文件、对话和工具日志。checkpoint 控制执行，导出文件供审阅。

审批绑定请求 ID、版本和产物哈希。检索前检查计划审批；写作前检查材料及其上游计划审批。修改生成新版本，不覆盖历史文件。进程退出后继续原审批点。

## 证据边界

区分正文、部分正文、摘要、搜索片段与演示数据；保存实际读取页码/文本块及原文摘录。PDF 失败允许摘要降级；不能仅凭搜索片段生成研究结论。不读取 OCR 或图表，不编造未见的实验数据。引用检查不等于事实正确性证明，材料仍须人工审批。

具体技术与启动方式见 `operation.md`，实施范围见 `implementation-plan.md`。
